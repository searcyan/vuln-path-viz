# 视觉规范与文案写法

这套风格只服务一件事：**让读者始终知道「当前这一行代码，是谁调的、往下会去哪」**。所有视觉决定都为此让路，不要为了好看而改。

两张样张（直接打开对照）：

- `examples/acme-reports/shots/step-10-fork.png` —— 完整样例停在第 11 步：进入 handler，红边（拒绝）与绿边（放行）通向右边的不同列
- `examples/acme-reports/shots/step-03-entry.png` —— 同一条链的入口：装饰器只写了「验 token」
- `examples/acme-reports/shots/step-16-summary.png` —— 结尾的复盘卡

## 配色（深色单主题，CSS 变量已在模板 `:root` 里）

| 用途 | 变量 | 值 |
|---|---|---|
| 页面底色 | `--bg` | `#0b0e14` |
| 左栏底板 | `--panel` | `#0f141d` |
| 卡片底 | `--card` | `#151a25` |
| 分隔线 | `--line` / `--line2` | `#2a3342` / `#1b222e` |
| 正文 / 次要文字 | `--txt` / `--dim` | `#e7ebf2` / `#8b97ab` |
| 语义：通过 / 拒绝 / 分叉 / 信息 | — | `#22c55e` / `#ef4444` / `#f59e0b` / `#60a5fa` |
| 普通调用边 | `both` | `#5d6b83` |

代码高亮 token：关键字 `#c792ea`、字符串 `#a5d6a7`、注释 `#6b7a90`（斜体）、函数名 `#82aaff`、数字 `#f78c6c`、被调函数名 `#f0b866`。

**语义色只能表达结局，不能表达"我觉得这行很重要"。** 重要 = 徽标 + 文案强调。

## 布局常数（`viz-template.html` 顶部）

| 常数 | 值 | 作用 |
|---|---|---|
| `COL_W` | 1180 | 相邻调用深度的列间距 —— 大到足够放下边上的行号标签和曲线车道 |
| `CARD_W` | 700~920 | 卡片宽度按最长行估算（`78 + 显示宽度 × 7.3`，夹在区间内） |
| 行高 | 21px | 一行代码 = 一行网格，保证边能精确落到某一行 |
| `GAP` | 56 | 同列相邻卡片间距 |
| 左栏 | 392px 固定 | 讲解栏；右侧画布自适应 |

同列卡片自上而下按 `cards[]` 顺序排列；卡片高度由真实 DOM 量出来后再回填 `y`，所以**不要在 CSS 里改行高或字号**，否则连线会错位。

一个场景的合适规模：**8~18 张卡片、10~36 步**。超过 18 张卡片读者会丢，超过 36 步建议拆成两个 scene（或两份文件）。

## 行级状态（这三个是核心，别混）

| 类 | 视觉 | 含义 |
|---|---|---|
| `.row.jump` | 行尾 `↗` + 左缘淡蓝 2px | 这一行会调用别的函数（有出边） |
| `.row.src` | 橙色左缘 3px + 淡橙底 | **当前步的调用发起行**，出现在父卡片里 |
| `.row.hit` | 蓝色左缘 3px + `▶` | **当前步命中的那一行**，出现在当前卡片里 |

配合卡片透明度：非当前卡片 0.42，当前卡片 1 且描边发亮。

## 徽标（`badge` 的第二个字段）

类型只有四种，词只用这些：

| 类型 | 颜色 | 常用词 |
|---|---|---|
| `info` | 蓝 | 起点、背景、鉴权入口、查库、返回上层、合并、落盘、时序、复盘、说明 |
| `warn` | 橙 | 关键、分叉点、换身份、前置条件、记住这里 |
| `bad` | 红 | 拒绝、抛出、结果、漏洞本体、落点 |
| `ok` | 绿 | 通过、捷径、放行、返回上层、第三个请求 |

一屏只出现一个徽标；它回答"这一步的性质"，不是标题的复读。

## 文案写法（决定这页好不好看的关键）

每一步 `text` 是**三段式**，都在 2~4 句话内：

1. **发生了什么** —— 这一行代码做了什么，用平实的动词。`它把数据库里的环境变量写进进程环境。`
2. **为什么值得停一下** —— 这一行与漏洞的因果关系，或读者容易误解的点。`这就是「改配置」变成「读任意文件」的落点。`
3. **下一步去哪** —— 一句指路。`接下来三步，就是「普通 key 被拦」的全过程。`

硬性要求：

- **事实加粗**：`<b>` 只给读者必须记住的那半句，每步 1~2 处，不要整段加粗。
- **代码用 `<code>`**：行内出现的标识符、字段名、状态码都包 `<code>`，与正文区分。
- **不许出现**：「可能 / 大概 / 应该是 / 一般来说」这类没核实的词。是推断就写「推断」并说明依据。
- **不复述标题**：`title` 是结论，`text` 讲why，别重复。
- **单步 ≤ 420 字**（lint 会 warn）。讲不完就拆两步 —— 拆步永远优于长段落。
- **术语一次定型**：同一个函数/对象，全篇只用一种称呼（`valid_token` 就叫 `valid_token`，不要一会儿"token 对象"）。
- **行号引用**：正文里说「第 N 行」时，N 必须在图里有卡片展示（lint 会提示），否则读者无处可对。
- **中文标点**：正文用全角，代码与标识符保持原样；中英文之间不加空格也可以，但全篇一致。

## 标题与序号

- `title` 形如 `⑤ 一行代码决定你能否进门`：**带圈序号 + 一句结论**，不超过 24 字。
- 序号表：`① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩ ⑪ ⑫ ⑬ ⑭ ⑮ ⑯ ⑰ ⑱ ⑲ ⑳ ㉑ … ㉟`。
- 第 1 步用 `⓪`（背景），第 2 步从 `①` 起 —— 这样 `⓪` 天然读作"第零步/前提"。
- 步骤列表左侧另有一列 `01 02 03`（页面自动生成），所以标题里不要重复数字。
- 超过 35 步：拆场景，不要发明第 36 个圈号。

## 复盘卡（每条路径必须有）

最后一张 term 卡片，编号写在 `fn` 里（如 `复盘：两个条件，缺一不可`），正文 3~5 条：

1. 漏洞成立需要哪几个条件（**缺一不可**的写法：`(1) … (2) …`）
2. 修复改了哪里（版本号 + 具体判断）
3. 复现最小路径（版本 + 需要的 key/开关 + 几次请求）
4. 边界：哪些前提不满足时打不通

## 交互（引擎已实现，别禁用）

- 左栏：「上一步 / 下一步」；点击步骤列表任意项跳转
- 键盘：`→` / `空格` 前进，`←` 后退
- 画布：拖动平移，`Ctrl+滚轮` 缩放，`总览` 一屏看全图再点「回到当前」
- 点击任意卡片：在该卡的多个步骤之间循环（头部 `第 N…M 步 · k 处` 提示有几步停在这里）
- 链接：`?scene=KEY&step=N`
